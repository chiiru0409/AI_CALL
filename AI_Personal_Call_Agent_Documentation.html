1. Executive Summary & Problem Formulation

Modern smartphone users face a relentless barrage of spam calls, aggressive telemarketing, banking scams (KYC expiration and OTP phishing), and repetitive routine calls (such as delivery status confirmations and college notices). Traditional call-blocking apps rely heavily on invasive cloud contact syncing, third-party databases, and passive number blacklisting. None provide autonomous, contextual voice interaction capable of conversing with callers on the user's behalf while keeping private data strictly confidential.

AI Personal Call Agent solves this paradigm by acting as a native Android cellular dialer integrated directly into the Android Telecom Framework. It can autonomously answer incoming cellular phone calls, conduct natural multi-turn conversations in English, Telugu, Hindi, or Telugu-English code-mixed dialect, consult user-approved knowledge, escalate emergencies (hospital/family alerts), reject scams, record speaker-labeled transcripts, and extract actionable follow-up items into a local SQLite Room database—with zero reliance on external cloud storage.

Core Value Proposition
1. Native Telecom Integration: Operates as the official Android Default Dialer (InCallService) with pre-answer filtering (CallScreeningService).
2. Zero-Trust Identity Isolation: Caller claims (e.g. "I am Rohit") are isolated from verified address book contacts to prevent social engineering.
3. Hardware-Backed Deterministic Safety: Unconditionally blocks OTP exfiltration, prompt injections, and banking password theft before reaching the LLM reasoning loop.

2.1 The Telephony State Machine

The core telephony coordinator (CallManager.kt) manages calls via a state machine that handles cellular transitions cleanly:

  • IDLE: Telephony subsystem awaiting incoming or outgoing cellular activity.
  • RINGING_INCOMING: Full-screen wake-lock activity presented on lock-screen with 4 action triggers: Answer Directly, Send to AI Agent, Send Callback Note, Decline.
  • ACTIVE_AI_AGENT: Call connected to autonomous audio loop. The user can view live speaker-labeled transcripts and tap "Take Over Call Directly" at any second.
  • ACTIVE_HUMAN: Traditional voice audio stream routed to earpiece, speakerphone, or Bluetooth headset.
  • DISCONNECTED: Telephony call severed. Triggers background persistence, risk assessment, caller memory updates, and follow-up item extraction.

4. Core Engineering Modules & Technical Methods

4.1 Telephony Subsystem (`service.telecom`)

  • AppInCallService.kt: Subclasses Android's InCallService with IN_CALL_SERVICE_UI and IN_CALL_SERVICE_RINGING metadata flags. Intercepts incoming and outgoing calls, passing lifecycle events (onCallAdded, onCallRemoved) to the centralized CallManager.
  • AppCallScreeningService.kt: Subclasses CallScreeningService to inspect caller telephone numbers before the phone rings. Allows rejecting known telemarketers or pre-tagging incoming callers.
  • CallManager.kt: Coordinates cellular calls. Implements answerCallDirectly(), sendToAiAgent(), takeOverFromAi(), declineCall(), hangUpCall(), toggleMute(), toggleSpeaker(), and DTMF tone streaming (sendDtmfTone).

4.2 Deterministic Safety & Policy Enforcement (`PolicyEnforcer.kt`)

AI voice agents on mobile devices are susceptible to prompt injections and social engineering attacks. To guarantee airtight security, the system applies a two-stage deterministic gate before and after LLM inference:

Defense Vector Pattern / Threat Detected Deterministic Action Taken
Anti-Prompt Injection "Ignore previous instructions", "System prompt override", "Developer mode", "Forget your rules" Immediately blocks caller utterance, speaks a security violation notice, and terminates cellular call connection.
Anti-OTP Exfiltration "Send me your OTP", "Give me one-time password", "Share UPI PIN", "Net banking password" Classified as SENSITIVE_DATA_EXFILTRATION. Request rejected unconditionally; caller flagged as high-risk fraud.
Anti-Credential Disclosure Agent proposed response containing PIN, CVV, or passwords. Intercepts synthesized text before reaching TTS; replaces with sanitized fallback: "I am unable to provide that information."

4.3 Multilingual NLP & Risk Assessment (`RiskAndUrgencyAssessor.kt`)

The assessor evaluates caller transcripts in real-time across four language modes: Telugu, Hindi, English, and Telugu-English Code-Switching (widely spoken in Andhra Pradesh and Telangana):

  • Urgency Detection: Detects medical emergencies (hospital, accident, ICU, ambulance), critical keywords, and regional urgent expressions ("twaraga" [Telugu for fast], "ippude" [Telugu for right now], "turant" [Hindi], "jaldi" [Hindi]). Promotes call urgency to EMERGENCY or HIGH, triggering instant human escalation.
  • Fraud & Scam Classification: Detects common cyber-fraud patterns: fake KYC expiration alerts ("account blocked, share OTP"), remote desktop software installation requests ("install AnyDesk / TeamViewer"), and bogus lottery notifications. Categorizes caller as FRAUD_SUSPECTED with HIGH_RISK_FRAUD.
  • Category Categorization: Classifies calls into DELIVERY (Swiggy, Zomato, Amazon), COLLEGE (exam, faculty, class), WORK, FAMILY, BANKING, SPAM, or OTHER.

4.4 Persistent Caller Memory & Zero-Trust Identity Isolation (`CallerMemoryRepository.kt`)

One of the most innovative systems developed in this project is the Caller Memory and Identity Claim Isolation architecture:

The "Imposter Caller" Vulnerability & How We Solved It
If an unknown caller calls and says "Hi, I am Rohit from your class", naive AI systems might permanently rename the contact to "Rohit" and trust them in future calls. Our architecture enforces strict isolation: caller self-claims are stored under claimedName with isVerified = false and trust score capped at 0.40. Only numbers matched against the local device address book (READ_CONTACTS) receive isVerified = true and high trust (0.85).

 | Preferences: None

4.5 Phone Number Normalization Algorithm (`PhoneNumberUtils.kt`)

To ensure accurate caller memory lookups regardless of cellular carrier formatting, all numbers undergo deterministic normalization into standardized E.164-compatible strings:

  • Strips spaces, dashes, brackets, and periods: +91 98765-43210 → +919876543210
  • Converts leading domestic zeros: 09876543210 → +919876543210
  • Formats bare 10-digit Indian numbers: 9876543210 → +919876543210
  • International numbers: +1 (555) 234-5678 → +15552345678

4.6 Autonomous Weekly Schedule Bitmask & Midnight-Crossing Engine

Users can define active operating windows for the AI agent (e.g., during work hours or late night sleep hours). The schedule evaluation engine uses a 7-bit binary bitmask representing Monday through Sunday (1 << 0 to 1 << 6): 

// Midnight-crossing algorithm implementation (e.g., 22:00 PM to 06:00 AM):
if (schedule.crossesMidnight || schedule.startMinuteOfDay > schedule.endMinuteOfDay) {
    // Active if after night start OR before morning end
    currentMinute >= schedule.startMinuteOfDay || currentMinute < schedule.endMinuteOfDay
} else {
    // Normal single-day window (e.g., 09:00 AM to 17:00 PM)
    currentMinute >= schedule.startMinuteOfDay && currentMinute < schedule.endMinuteOfDay
}

4.7 Room Database Schema & Zero-Data-Loss Migrations (`AppDatabase.kt`)

Offline persistence is anchored by an SQLite database (aicall_database.db) managed via Room v3. To ensure that schema updates never cause crashes or wipe user data, explicit SQL migrations were implemented and verified:

  • MIGRATION_1_2: Adds unresolvedRequests and preferences columns to caller_profiles; adds processingError to call_records.
  • MIGRATION_2_3: Adds priority column with default 'NORMAL' to the action_items table.
  • MIGRATION_1_3: Direct composite migration path from legacy version 1 to current version 3.
